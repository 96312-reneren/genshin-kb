# 原神知识库 · Genshin Knowledge Base

一个**本地运行、离线可用**的原神资料与分析知识库。数据存放在一个 SQLite 文件里，可视化页面由数据库实时导出。
仅用于**个人学习与研究**。

---

## 二、目录结构

```
原神知识库/
├── genshin_kb.db          ← 知识库本体（SQLite 单文件，24 张表）
├── README.md              ← 本文件
├── AGENTS.md              ← 给 AI 看的记忆文件（改这个项目前先读它）
├── 数据来源与合规说明.md    ← 数据出处与版权说明
├── 那维莱特运营事故与数值膨胀长期影响分析报告.md    ← 专题报告（可编辑）
├── 那维莱特运营事故与数值膨胀长期影响分析报告.docx  ← 专题报告文档版（可编辑）
├── site/
│   ├── index.html         ← 可视化页面（自包含，双击打开）
│   ├── template.html      ← 页面模板（改这里可以换界面）
│   └── data.json          ← 数据库内容快照（便于二次开发）
├── maf/                   ← 内容观察工作台（独立子项目，另有自己的 README）
│   ├── README.md
│   ├── data/              ← app.db（人工投喂线）+ crawl.db（历史第三方镜像线）
│   ├── app/               ← 本地桌面应用（bottle + 单页前端）
│   ├── out/               ← 批量产物：PPT / Word / PDF / 图
│   ├── tests/             ← 112 项离线测试（unittest）
│   └── myvenv/            ← 它自己的虚拟环境（不需要动知识库也能跑）
└── scripts/
    ├── schema.sql         ← 数据库表结构定义
    ├── kb_data.py         ← 手写内容都写在这里（1-19 号表）
    ├── init_db.py         ← 建库 + 灌数据  → 生成 genshin_kb.db（会清空 maf 表）
    ├── import_maf.py      ← 从 maf/data/*.db 导入批量处理结果（20-24 号表）
    ├── build_site.py      ← 读数据库 → 重新生成 site/index.html
    ├── query.py           ← 命令行查询工具
    ├── md_to_docx.py      ← 把 Markdown 报告转成可编辑的 .docx
    └── smoke_test.js      ← 页面脚本的自检（可选）
```

**两个仓库的关系**：`maf/` 原本是一个独立仓库（MAF 内容观察工作台），现已移动为本仓库的子目录。
它负责「一批文本材料 → 模型概括 → 时间轴 → 观察报告 → PPT/Word/PDF」；
知识库负责「把这些结果和已有的角色 / 版本 / 运营分析放在一起看」。
两者用 `scripts/import_maf.py` 单向连接，**maf 不知道知识库的存在，知识库也不依赖 maf 的代码**。

## 三、数据库

用的是 **SQLite 3**。选它的理由很简单：这个项目要的不是"扛并发"，而是**单文件、零配置、能长期保存、随时能查**。整个知识库压在一个文件里，拷走就能带走；同时它又是标准 SQL 数据库，可以用任何工具打开。

### 怎么查

**用附带的工具（不用写 SQL）：**

```bash
python scripts/query.py tables                          # 看有哪些表、各多少行
python scripts/query.py teams --archetype 蒸发            # 按体系查队伍
python scripts/query.py teams --name 超绽放               # 查单套队伍（含成员）
python scripts/query.py chars --element 火 --rarity 5     # 筛选角色
python scripts/query.py ops --grep 树脂                   # 搜运营分析
python scripts/query.py abyss                            # 深渊全部内容
```

**直接写 SQL：**

```bash
python scripts/query.py sql "SELECT name,element,weapon FROM characters WHERE rarity=5 ORDER BY element"
```

**或者用图形界面**：任何 SQLite 客户端都行，推荐免费的 **DB Browser for SQLite**，双击 `genshin_kb.db` 就能浏览和查询。

## 四、怎么更新

数据发生变化（版本更新、深渊换期、价格调整）时的完整流程：

1. 改 `scripts/kb_data.py`（手写内容都在这个文件里，中文注释齐全）
2. 依次运行：
   ```bash
   python scripts/init_db.py      # 重建数据库（注意：会清空 maf 的 5 张表）
   python scripts/import_maf.py   # 从 maf/data/*.db 重新导入批量结果
   python scripts/build_site.py   # 重新生成网页
   ```
3. 刷新 `site/index.html` 即可

**只改 maf 的材料** → 在 `maf/` 里跑完它自己的流程后，只需：

```bash
python scripts/import_maf.py && python scripts/build_site.py
```

不需要动 `init_db.py`。想看会导入什么而不写库，加 `--dry-run`。

**只需要改界面** → 编辑 `site/template.html`，然后运行 `build_site.py`。

**改专题报告** → 编辑 `那维莱特运营事故与数值膨胀长期影响分析报告.md`，需要 Word 版时再跑一次：

```bash
python scripts/md_to_docx.py 那维莱特运营事故与数值膨胀长期影响分析报告.md
```

注意 **`.md` 是唯一的手改入口**。`.docx` 是生成物，直接改 docx 不会同步回 Markdown；报告里的数字来自 `kb_data.py`，改了数据后记得一并核对报告正文。

**版本更新后建议核对的地方：**

- 深渊每期的敌人组合与「渊月祝福」（每半月换一次）
- 新版本的角色 / 武器（`characters` 表里标了「待核验」的需要优先复核）
- 卡池概率与价格（一般稳定，但规则调整过：例如 5.0 起武器池命定值由 2 点降为 1 点）

核对渠道：游戏内「祈愿 → 详情」（概率）、游戏内深渊界面（当期敌人与祝福）、官方公告（版本与价格）。

### maf 子项目怎么跑

`maf/` 有自己的虚拟环境和测试，和知识库互不干扰：

```bash
cd maf
.\myvenv\Scripts\python.exe -X utf8 -m unittest discover -s tests -t tests -p "test_*.py"
.\run_tests.ps1          # 同样的测试，带彩色输出（注意它在 stderr 有日志时会误报失败）
.\run_all.ps1            # 跑一遍批量流程
```

它的图形界面用 `.\run_app.bat` 打开（本地 `127.0.0.1` 上的桌面应用，需要本地 ollama 或配置云端凭据）。

**`maf/` 是独立的**：把它整个删掉，知识库仍然能正常构建，只是「观察材料」标签页会变成空表。
反过来说，**知识库的构建脚本一行都不 import maf 的代码** —— 桥接脚本只用 `sqlite3` 读它的数据库文件。

### 20-24 号表的合规约定

`maf_items.body` 只对**人工投喂线**（`origin = '人工投喂'`）保留正文；第三方接口镜像线的条目一律留空，
理由写在同行的 `body_policy` 字段里。需要连镜像线的正文一起入库时，

```bash
python scripts/import_maf.py --include-third-party-body
```

显式打开这个开关 —— 默认不开，是为了让「库里有没有上游原文」这件事必须被主动选择一次。

## 五、数据基准与已知限制

- **数据基准版本**：7.x（2026 年 10 月核对）
- **已核验的高置信度数据**：抽卡概率与保底、付费档位价格、树脂机制、深渊结构
- **需要你自己复核的数据**：
  - 深渊每期的具体敌人与祝福（时效性极强，本库只写机制不写当期）
  - `characters` 表中标注 **「待核验」** 的较新版本角色（页面会用红色标签标出）
  - 标注「社区测算」的原石产出量级（非官方数据，仅供量级参考）
  - **「事件复盘」中的深渊血量与队伍 DPS 数字**：全部为社区逐版本统计，官方从未公布血量历史数据，只能看趋势与倍数，不能当精确值
  - **「事件复盘」中的游戏收入数字**：为第三方机构估算，非官方财报，只能描述趋势方向
  - 事件类的因果分析是**本库作者的分析**，不是事实陈述；每条影响都标了置信度，请连置信度一起看
  - **「观察材料」里的模型概括与观察报告**：由本地 `qwen3:8b`（少数为云端模型）生成，可能读错、可能遗漏；
    它们是「这批材料大概说了什么」的索引，**不是官方表述**，引用时请回到材料出处
  - **「观察材料」里第三方镜像线的正文**没有入库（合规取舍），页面上只有标题、日期、出处与派生概括
- **本库不包含**：深渊每期实时数据、角色数值面板、圣遗物词条推荐、活动日历。
  这些内容时效性强，建议直接看游戏内或官方公告。

## 六、版本管理与备份

这个目录本身是一个 git 仓库，数据库与产物（含 `.db`、`.docx`、`.pptx`、`.pdf`）**都进版本库**，当作离线备份用。
`maf/myvenv/` 与各处 `__pycache__/` 通过 `.gitignore` 排除 —— 虚拟环境可以用 `maf/run_all.ps1` 之外的命令重建，
体积也没必要跟着历史走。

常规提交：

```bash
git add -A
git commit -m "说明这次改了什么"
git push
```

**注意**：`genshin_kb.db` 是二进制文件，每次重建都会整体换一份，git 存不下它的历史增量。
如果它开始明显拖慢仓库，可以把它从版本控制里移出去，改为定期另存备份。
